# Second local review — October 10, 2026

**Resolution:** all eight findings below were subsequently repaired locally and given regression checks. See [the repair report](repairs-20261010.md) and [current verification](../VERIFICATION.md#eight-review-findings-repaired--2026-10-10-unreleased). The remainder of this document preserves the original findings and their before-fix evidence; its line references describe that earlier source state.

This was a review, not another implementation pass. Application code was left unchanged; the existing build/test runner regenerated the portable files from that same source. The new files are this report and `research/review-20261010.cjs`, a repeatable diagnostic harness. Nothing was committed or pushed, and no existing desktop browser, OBS session, or native client was controlled.

## Confirmed findings

| Priority | Finding | Evidence and effect | Location |
|---|---|---|---|
| P2 | Announcement and resubscription text is omitted | Two `USERNOTICE` messages containing user text produced zero message callbacks. Only `PRIVMSG` reaches the renderer. This also omits shared announcements. These are messages Moltorino handles, not merely decorative notification banners. | `transport.js:78`, `transport.js:166` |
| P2 | Emote refreshes still permit stale overwrites | Resolving a newer refresh first and the older one last restored the older emote in both the app and provider cache. The previous freshness correction covers cosmetics registries, not `OverlayProviders.load()` or `OverlayApp.refresh()`. A manual refresh overlapping initial loading is one concrete trigger. | `app.js:67`, `providers.js:119` |
| P2 | One malformed provider response breaks unrelated providers and poisons its cache | A successful HTTP response containing FFZ `emoticons: {}` threw while parsing, despite valid BetterTTV data. The invalid FFZ payload was cached before parsing; a subsequent outage reused it and threw again. HTTP failure tests do not cover this. | `providers.js:122`, `providers.js:142` |
| P2 | Slide copies disagree when a layer's dimensions arrive late | A 96×32 overlay rendered at approximately 108px in the first Slide cell but 36px in the other two. `cloneNode(true)` copies neither load listeners nor later size corrections. Reproduced in Chromium, Firefox and WebKit after images decoded and load events settled. | `renderer.js:66`, `modifiers.js:149` |
| P2 | FFZ static image fallback is never used | The provider records a working static `fallbackUrl`, but failure of the animated URL immediately replaces the emote with text. The diagnostic returned `Broken` and zero image nodes even though its static image was available. | `providers.js:64`, `renderer.js:87` |
| P2 | Deferred radial-paint work can overwrite a newer paint revision | Applying a red radial paint before insertion queues a frame callback. Applying a blue revision with the same ID after insertion correctly turns the name blue, then the old callback turns it red again. Its guard compares only the ID, not the revision/paint object. Reproduced in all three engines. | `cosmetics.js:50` |
| P3 | Changing one badge rebuilds every badge for the message | Adding a second provider's badge replaced the original, unchanged badge node. The earlier preservation tests only compare entirely identical profiles. This causes avoidable image-node churn; animation continuity across a real change was not established. A failed image also invalidates the whole signature, so later updates can rebuild otherwise valid badges. | `renderer.js:97` |
| P2 | Twitch recovery has gaps before opening and after joining | The controlled socket test had zero watchdog timers before `onopen` and zero after successful `ROOMSTATE`. There is a join timer only after opening. A connection that stalls without a close/error event therefore has no application-level recovery deadline. The test establishes the missing guard; it does not claim to reproduce a physical network interruption. BetterTTV similarly relies on browser close/error events. | `transport.js:129`, `transport.js:143`, `transport.js:162`, `cosmetics.js:264` |

Suggested repair order: restore missing message text; isolate/validate provider data and extend freshness guards; close connection recovery gaps; correct Slide/fallback handling; then fix radial revision checks and reconcile badges individually.

For `USERNOTICE`, parse only supported message types with actual user content and apply the appropriate message flags. Do not convert every payment/system notice into ordinary chat. Twitch documents these command types in its [IRC reference](https://dev.twitch.tv/docs/chat/irc/#usernotice-command). Moltorino's [pinned handler](https://github.com/EEVA-inc/Moltorino7/blob/2c98aaf8004842e7a25ff8aa07a362f9056c51b3/src/providers/twitch/IrcMessageHandler.cpp#L929) also distinguishes shared notices and announcements.

## What passed, and what was ruled out

- Reran `npm test`: **96 passed**, zero failed. Reran the full existing Chromium browser suite: passed. These cases were absent from the existing suite, so those results do not contradict the findings above.
- Ran the new browser diagnostics in **Chromium, Firefox and WebKit on Windows**. The rendering and refresh issues reproduced in all three. Provider and transport diagnostics use controlled Node VM inputs; they are not network-outage observations.
- Checked current upstream HEAD: `3a668aed4349b4f5dfa7229b11ce45d40aa43e25`. Its only commit after the pinned `2c98aaf…` reference fixes startup opening. There were no changes to the badge/paint/provider and message-building paths compared for this review. The pinned cosmetic comparison is therefore still relevant.
- Two live public 7TV profile lookups successfully resolved both paint and badge IDs through the current code. The suspected old/new cosmetic-ID mismatch was not reproduced. This was an API/service check, not a full live-chat rendering test.
- A BetterTTV `lookup_user` with no badge leaves an earlier badge cached. The overlay does this, but so does the pinned [Moltorino handler](https://github.com/EEVA-inc/Moltorino7/blob/2c98aaf8004842e7a25ff8aa07a362f9056c51b3/src/providers/bttv/liveupdates/BttvLiveUpdateClient.cpp#L71). It is a shared limitation, not evidence of a parity regression, and is excluded from the eight findings.
- Moltorino's paint code applies shadows successively too; chained CSS shadows were not incorrectly flagged merely for compounding.
- Package and lockfile versions agree. Node 18 remains the optional server's stated minimum, while the README separately requires Node 20 for development tests; Playwright's Node 20 requirement is not a contradiction in the runtime instructions.
- Existing `git diff --check` completed without whitespace errors. Its line-ending notices were warnings, not failed checks.

## Reproduce

From the repository root, run:

```sh
node research/review-20261010.cjs
```

To choose another installed Playwright engine, set `OVERLAY_BROWSER=firefox` or `OVERLAY_BROWSER=webkit` using your shell, then run the same command. In PowerShell: `$env:OVERLAY_BROWSER='firefox'`.

The harness records observations; exit code zero means the diagnostic completed, **not** that the application passed new acceptance tests. It uses fixture HTTP interception, simulated socket callbacks, and locally injected messages. It sends nothing to Twitch.

Results are in ignored `test-results/review-20261010-{chromium,firefox,webkit}.json`. Existing-suite logs are `test-results/review-20261010-node.txt` and `test-results/review-20261010-browser.txt`.

## Remaining verification boundaries

Actual macOS/Linux execution, Safari/Brave/Chrome branded applications, OBS's embedded browser, physical network-loss recovery, and a native Moltorino visual comparison remain untested for these changes. Source/binary identity, Qt-versus-CSS glow/rasterization, GIF-dependent modifier timing, native account/local overrides, 7TV personal emotes, and native disk-cache/bootstrap behavior remain the previously documented differences. This review does not turn them into verified parity.

Shared Chat coverage currently concerns origin/role badges, not full source-channel emote catalogs or every shared notice. Live emote changes are still polled every five minutes; the new BetterTTV socket currently handles badges only. These are feature boundaries to keep explicit when describing parity.
