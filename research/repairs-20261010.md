# Eight local repairs — October 10, 2026

All eight confirmed findings in [the second review](review-20261010.md) are addressed in the working tree. No commit, push, release, existing desktop browser, or native app control was used. Earlier local changes remain in place.

| Finding | Result | Regression evidence |
| --- | --- | --- |
| Missing announcement/resubscription text | Supported `USERNOTICE` types with actual user text follow the normal message path, preserving names, badges, emotes, IDs and subscription flags. Shared announcements are accepted; mirrored subscription/payment notices are suppressed. Empty or unknown notices do not become chat rows. | Socket parsing, channel filtering, deduplication, Unicode offsets, native shared-notice rules; parsed resubscription rendered by the production app in both modes. |
| Older emote refresh replaces newer data | App refreshes and each endpoint cache carry sequence numbers. An older completion cannot replace a newer completed result. | Forced completion order in both the provider cache and app, including initial loading overlapping a manual refresh. |
| Malformed FFZ poisons its cache and blocks other providers | Responses are parsed into a scratch map before caching. Invalid responses use the last valid data for that endpoint, if available, without blocking unrelated providers. Collection checks cover FFZ, BTTV, 7TV and Twitch badges. | Invalid FFZ `emoticons` with valid BTTV, followed by an outage; malformed 7TV and Twitch badge collections; provider cache race. |
| Slide copies have incorrect late layer widths | Every original and cloned image gets load/error handling. Unknown overlay dimensions update every Slide cell in place. | A 96×32 overlay reaches 108px in every cell at 36px emote size. Paused motion clocks remain at 543ms. |
| FFZ static fallback unused | Each image tries its safe static fallback once after an animated URL fails. A failed base becomes text only if that fallback also fails; a failed overlay is removed from all cells. | Broken animated URL loads a real static fixture; failure of both URLs produces text without an image node. |
| Deferred radial paint overwrites a new same-ID revision | Deferred work checks the element's application revision, rather than only the paint ID. Clearing or updating a paint invalidates earlier callbacks. | A detached red radial paint followed by an attached blue revision with the same ID remains blue after the queued frame. |
| Badge updates rebuild unrelated images | Reconcile badges individually by provider, ID, URL and duplicate occurrence. Order/title/background updates reuse matching nodes. Failed images are isolated and have a 30-second retry cooldown. | Add/reorder/metadata changes preserve both unchanged nodes; repeated updates after another badge fails preserve the valid node and do not recreate the failed image during cooldown. |
| Connections can stall without recovery | Twitch has 20-second handshake and join deadlines, then a six-minute inbound-idle deadline. BetterTTV has a 20-second handshake deadline and renews its subscription every 15 minutes. 7TV's hello/heartbeat deadlines now retire sockets and schedule retries directly. Late callbacks cannot act on replacements. | Fake sockets never emit close events. Deadline, keepalive, constructor failure, stale callback/channel-switch, read-only subscription and shutdown cases verify recovery and cancellation. |

## Source basis

USERNOTICE content types and shared-notice suppression follow Moltorino source commit `2c98aaf8004842e7a25ff8aa07a362f9056c51b3`, [IrcMessageHandler.cpp](https://github.com/EEVA-inc/Moltorino7/blob/2c98aaf8004842e7a25ff8aa07a362f9056c51b3/src/providers/twitch/IrcMessageHandler.cpp#L929), together with [Twitch's USERNOTICE specification](https://dev.twitch.tv/docs/chat/irc/#usernotice-command). Only trailing user-written content is rendered, not `system-msg` notification banners. Native-supported content types are `sub`, `subgift`, `resub`, `bitsbadgetier`, `ritual`, `announcement`, `viewermilestone`, `modiversary` and `socialsharingbadge`; `sharedchatnotice` uses `source-msg-id`.

[BetterTTV's documented WebSocket protocol](https://betterttv.com/developers/websocket) provides `join_channel` and `lookup_user`, without an application heartbeat. The 15-minute connection renewal is this overlay's recovery policy, not a provider-required heartbeat. It retains known badges through renewal and sends no viewer presence announcements. Twitch's six-minute inbound deadline is also an overlay policy; server PING traffic resets it. Retries use bounded backoff.

## Validation and delivery

`tests/repair-findings.test.cjs` adds 14 Node tests, bringing the complete Node suite to 110 passing tests. `tests/review-regressions.cjs` turns the review reproductions into assertions, integrated into the normal browser suite. The initial assertions reproduced the review failures before the repairs. The final full suite passes in Chromium, Firefox and WebKit on Windows, including source-script and rebuilt portable-file cases. Fixture image tests wait for completed load/error handling, rather than assuming it finishes within a fixed 100 milliseconds.

The build regenerates `standalone-template.html`, `dist/chat-channelname.html` and `dist/chat-jynxzi.html`. Existing downloaded files must be replaced with a newly built file to receive these code changes; renaming the replacement to `chat-yourchannel.html` keeps the channel-selection workflow.

A separate live `file://` check on a renamed portable file connected anonymously to Jynxzi and loaded 984 emotes despite two channel-provider HTTP 404 responses. It also connected to 7TV and loaded 348 Moltorino preference records. See [VERIFICATION.md](../VERIFICATION.md#eight-review-findings-repaired--2026-10-10-unreleased) for the time, reports, commands and exact limits. No user cosmetic assignment was observed in that short check. Actual OBS, Safari, native Qt rendering, macOS/Linux execution and physical network interruptions remain outside this validation.
